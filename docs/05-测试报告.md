## 1. 测试策略

| 层 | 工具 | 范围 | 目标 |
|---|---|---|---|
| 接口 / 业务逻辑 | pytest + FastAPI TestClient + 临时 SQLite | 认证、资料、推荐、匹配、消息、AI、房间、通话、积分、举报 | 覆盖 TC01–TC40 的业务规则与异常分支 |
| 端到端（E2E） | pytest + Playwright（Chromium，420×860） | 真实浏览器 + 真实后端进程（独立临时库） | 主流程可用、AI 不自动发送、权限不泄露 |
| 人工验收 | `screenshots/` + 演示台 | 18 个页面视觉与交互 | 与原型一致、无遮挡、无控制台错误 |

### 测试夹具（为什么这么设计）

- **独立临时数据库**：每个测试会话一个新 SQLite 文件，测试间不串数据；`conftest.py` 提供 `maker()` 快速造用户。
- **确定性 AI**：`CROSSMATE_AI_MODE=mock`，AI 输出可预测，才能断言“保留否定/数字”。
- **时间可控**：`util.advance()` 推进时钟，测试 24h 观察期、5 分钟验证码过期、7 天活跃度而不真的等待。
- **E2E 后端进程**：`subprocess` 拉起真实 `app.main`，`PYTHON_FOR_APP` 可指定能 import fastapi 的解释器；`?e2e=1` 暴露最小桥接口（拿演示 token、发起 API 调用），**不改变产品逻辑**。

### 4.2 可点性测试（`e2e/test_clickable.py`）

背景：用户反馈“连最简单的语言都切换不了”。排查发现 Settings 的 Language 行带 `›` 箭头、看起来可点，
实际是个 `<span>`，没有任何事件监听——**之前的 E2E 只跑主流程，从没点过每个控件**。

判据：对 11 条路由（启动页/登录页/首页/发现/会话/房间/通知/积分/我的/隐私/设置）里所有
`button:not([disabled])`、`[role=switch]`、`[data-go]/[data-back]/[data-tab]/[data-demo]/[data-i]/
[data-l]/[data-goal]/[data-lang]`、`.list` 逐个真实点击，1.1 秒内出现以下任一变化才算“有反应”：
路由跳转 / `#view` 重渲染 / 弹层出现或变化 / toast / localStorage 变化 / select 值变化 /
`aria-pressed`、`aria-checked`、class 变化 / 元素被移除 / 发出新 API 请求 / 弹出 confirm 对话框。

排除项（写明理由）：当前所在 Tab（设计上只回顶部）；余额不足已 `disabled` 的 Redeem（禁用是对的）；
点击超时（被弹层遮住或已被移除，不算“点了没反应”）。

另有 `test_language_switch_changes_ui_and_persists` 专门盯用户报过的这条：点 Language → 中文，
断言底部 Tab 变成 首页/发现/房间/聊天/我的、退出登录按钮变“退出登录”、`<html lang="zh">`、
**刷新后仍记住中文**。

配套的 `e2e/audit_controls.py` 是会打印明细的审计脚本（`PASS/NOOP/ERR` 逐行），用于排查而不是回归。

**结果：12 个用例全部通过。**

| D21 | Chats 的 Matches / All 两个子标签内容一模一样 | 两个过滤分支都返回全量列表 | Matches = 已匹配且还没聊过（带数量角标），All = 全部；按最近活跃排序 |

| D23 | 社交登录看起来是真实 Apple / Google 授权 | 后端是 mock，界面上没有任何提示 | 先 `confirm` 说明“演示模式、未接入真实 OAuth”，成功后 toast 也写明未真实授权 |
| D24 | 登录页的《条款》链接点不开 | `href="#"` 改了 hash，路由回落到启动页 | `preventDefault` + 弹层展示 |
| D25 | 通话页静音/扬声器按钮点了没反应，像坏了 | 只是 UI 状态，没有真实音轨 | 加 `aria-pressed` + toast 明说“演示：仅界面状态”，提示文案写清没有真实音频 |
| D26 | 设置页昵称、通知两行同样“看着能点、点了没反应” | 只有展示，没有绑定 | 昵称 → 弹层输入并 `PATCH /users/me/profile`；通知 → 弹层开关，存 `localStorage.cm_notify` |
| D27 | 演示账号登录偶发失败，且失败后像“卡住了” | `loginDemo` 用内存里的 `state.devices` 快照取缓存验证码，`localStorage` 被清理或服务端重置后快照已过期，先白吃一次 429 限流 | 每次登录前从 `localStorage` 重新读缓存；429 时按 `retry_after` 等待 |

## 6. 未覆盖与风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 真实模型行为 | mock 模式无法验证真实模型的语义保真 | `AI_MODE=real` 时接公司网关；上线前用 50 条人工标注样例做离线评估（否定/数字/称谓） |
| 实时性 | 聊天是 3s 轮询，不是 WebSocket | v0.3 改 SSE/WS；当前用轮询保证“可演示、可测试” |
| 并发压力 | SQLite 单连接 + 锁，适合演示与单机 | 生产换 PostgreSQL；`db.tx()` 已是事务边界，迁移成本可控 |
| 静态资源 404 | 浏览器请求 favicon 报 400 | 无害；生产加 favicon |
| 本地化范围 | 已支持 en/zh/ja/es，但只翻译**界面骨架**；用户产出内容（昵称、聊天、房间名、AI 建议）与后端提示语仍是原文 | 这是刻意的：翻译用户内容等于造假。后端提示语多语言需后端配合 |
| E2E 桥接口 | `?e2e=1` 与 `/admin/e2e` | 非 mock 环境默认 403（`CROSSMATE_ALLOW_E2E`），生产不暴露 |

## 7. 结论

- P0 门禁通过，可进入演示/内测。
- 数据合规相关的 4 条红线（AI 不发送、不冒充、敏感属性不排序、积分不买曝光）均有自动化断言，回归时不会悄悄退化。
