# CrossMate 产品方法库（按工作场景归类）

> 读者：准备 AI PM / 社交产品经理面试的人。  
> 用法：先看“场景”，再记“怎么用”，最后看 CrossMate 里对应的**真实产出**——面试时讲产出，比背定义有说服力。  
> 对应岗位：① 杭州图灵求索 · 社交产品经理　② 杭州思绪涌现 · 产品经理（海外社交）

---

## 0. 一张图：方法与产品周期的关系

```
发现问题 ──► 定义机会 ──► 设计解法 ──► 排序取舍 ──► 交付上线 ──► 度量复盘
  访谈/问卷    画像/分层/    用户故事/     KANO/RICE/    PRD/评审/    北极星/OKR/
  5Why/竞品    旅程图/JTBD   故事地图/原型   MoSCoW/ICE    MVP/可用性    漏斗/留存/
  SWOT                                  价值-成本      测试/A/B      同期群/PDCA
```

一个常见误区：把方法当“清单”挨个用。正确姿势是**每个阶段选 1–2 个最足以支撑决策的方法**，其余只作为补充证据。

## 场景 A：判断“要不要做”

### A1 用户访谈（半结构化）

- **怎么用**：一次 30–45 分钟，少问“你想要什么”，多问“上次发生是什么时候、你当时做了什么”。每场 3–5 个核心问题，追问“为什么”两到三次。
- **输出**：5–8 条带原话的洞察 + 反证（不符合预期的访谈也要记）。
- **CrossMate**：访谈 12 名印尼/巴西用户得到核心原话——“匹配了但不知道怎么开口”。这条直接变成北极星候选（周均有意义对话用户数），而不是 DAU。
- **反模式**：只访谈重度用户；问“你会不会用”。

### A2 问卷

- **怎么用**：先用 3–5 场访谈得出假设，再用问卷量化（样本 ≥200）。题目避免双管、避免诱导。
- **CrossMate**：验证“破冰困难”是否普遍——问卷里“匹配后有 3 次以上打开聊天又退出”的占 41%，支撑做 AI 破冰。
- **注意**：问卷不适合发现新问题，只适合验证。

### A3 5W1H / 5 Why

- **5W1H**：把一个模糊需求拆成 What/Why/Who/When/Where/How。例：“要做 AI 聊天助手” → What 是建议还是代发？Who 是新人还是社恐？When 是匹配后还是任何聊天中？
- **5 Why**：连续追问根因。CrossMate 的追问链：聊天率低 → 不知道说什么 → 怕说错 → 跨语言/跨文化 → **需要“有依据的开口素材”**（而不是更多匹配）。
- **输出**：问题定义一句话，写进 PRD §1。

### A4 竞品分析

- **怎么用**：选 3 个直接竞品 + 1 个跨界参照；维度按“用户路径”而非“功能列表”。
- **CrossMate 结论**：Litmatch / Yubo / Tinder 共同的缺口是“推荐不解释 + AI 介入方式粗糙（要么全自动要么没有）”。跨界参照 Duolingo：用“给理由”降低羞耻感。
- **输出**：一张对比表 + 一句“我们不做什么”。

### A5 SWOT

- **怎么用**：S/W 写内部（团队、数据、成本），O/T 写外部（监管、平台政策、竞品）。避免写成优点清单。
- **CrossMate**：W——没有实时音视频基础设施；O——AI 成本下降让“可解释推荐”变得可行；T——各市场监管对 AI 生成内容标注趋严（这正是我们把“AI 从不代发”写死的理由）。

## 场景 B：理解用户

### B1 用户画像

- **怎么用**：画像要能指导决策（影响哪些功能优先级），不是美术作品。每个画像写“目标 / 触发场景 / 反感点 / 判断标准”。
- **CrossMate**：4 个画像见 PRD §1.2（P1 跨文化交友者、P2 语言交换者、P3 深夜陪伴者、P4 谨慎新用户）。
- **面试讲法**：“P4 谨慎新用户决定我们的默认隐私是 matches_only，而不是 public。”

### B2 用户分层

- **怎么用**：按行为分层（新用户 / 激活用户 / 沉默用户 / 高价值用户），每层给一个“下一步动作”。
- **CrossMate**：分层后给不同 AI 配额优先级——新用户破冰 10 次，活跃用户 5 次 + 通话准备（数据表明活跃用户更缺“通话前的话题”）。

### B3 用户旅程图

- **怎么用**：横向是阶段（发现→匹配→聊天），纵向是行为/情绪/触点/痛点/机会。
- **CrossMate**：情绪最低点出现在“匹配成功页”——惊喜之后立刻焦虑。于是 P07 放“为什么推荐你们聊天”，把焦虑转成话题。

### B4 JTBD（Jobs To Be Done）

- **句式**：“当我____时，我想____，这样____。”
- **CrossMate**：“当我刷到一个有意思但语言不同的人时，我想快速找到共同点并自然开口，这样不会尴尬地放弃。” → 推导出 match_hint + 破冰建议 + 翻译。

## 场景 C：定义解法

### C1 用户故事

- **格式**：`作为<角色>，我希望<能力>，以便<价值>`，外加验收条件。
- **CrossMate 示例**：

```
作为刚匹配的用户
我希望看到“为什么推荐我们聊天”
以便我能自然地发出第一句话
验收：卡片/匹配页显示 match_hint；只使用公开字段；无共同点时不展示
```

### C2 故事地图

- **怎么用**：横轴是用户活动（登录→发现→喜欢→匹配→聊天→通话），纵轴是版本切片（v0.2 / v0.3）。同一行内从上到下就是“最小连贯体验”。
- **CrossMate**：v0.2 覆盖每一列的最小闭环；v0.3 补充实时性与真实模型灰度。

### C3 用户流程图

- **怎么用**：画出所有分支（成功/失败/超时/越权）。PRD 的“异常流”就是流程图的分支清单。
- **CrossMate**：见 PRD §5；异常流表格是流程图缺失时最常见的漏洞来源。

### C4 原型

- **怎么用**：低保真先测信息架构，高保真再测视觉。原型阶段只解决“能不能看懂下一步做什么”。
- **CrossMate**：18 个页面的 PNG 原型（`页面/`，25 张）→ 实现截图逐页对照。

### C5 PRD

- **怎么写才好评审**：一页纸 TL;DR → 背景 → 指标 → 范围（含**不做**）→ FR 验收 → 异常流 → 修正记录。
- **CrossMate**：`docs/01-PRD-v0.2.md`，其中“14 条设计修正”是面试中最好的谈资：它证明你不是抄需求，而是判断过需求。

### C6 需求评审

- **准备**：提前 1 天发文档，附“需要大家决策的 3 个问题”；会上只讨论分歧，不朗读文档。
- **CrossMate 评审产出**：研发提出“AI 自动发送更省事”，被以“信任与合规”否决，改为一键回填（这就是修正 C2）。

## 场景 D：排序与取舍

### D1 KANO

- **怎么用**：问卷分“有/没有”两题，判定 必备/期望/兴奋/无差异/反向。
- **CrossMate**：AI 破冰是**兴奋型**（没有也不影响用），翻译是**期望型**，举报是**必备型**。资源顺序：必备 → 期望 → 兴奋。

### D2 RICE

- **公式**：`(Reach × Impact × Confidence) ÷ Effort`
- **CrossMate 计算示例**：AI 破冰 Reach=周活 80%、Impact=2、Confidence=70%、Effort=8 → 14；实时 WebSocket Reach=100%、Impact=1、Confidence=50%、Effort=13 → 3.8。结论：先破冰，后实时。

### D3 ICE

- **怎么用**：Impact / Confidence / Ease 各 1–5 打分，快速对齐；适合早期几十个想法。
- **和 RICE 的区别**：ICE 更轻、主观；RICE 更能说服人（有时间维度 Reach）。

### D4 MoSCoW

- **CrossMate**：Must——登录/资料/匹配/聊天/举报；Should——AI 破冰、房间；Could——通话准备、数据导出；Won't（本版）——录音、付费。

### D5 价值—成本矩阵

- 四象限里优先“高价值低成本”；**高价值高成本的别砍，要拆**（把 WebSocket 拆成“轮询 + 未读角标”先上线）。

### D6 MVP

- **定义**：能验证核心假设的最小闭环，而不是“功能最少”。
- **CrossMate MVP 假设**：“有了有依据的开口建议，匹配会真的聊起来”。MVP 只做：匹配成功页 reasons + 破冰建议 + 回填不发送。其余（房间、通话、积分）是为了完整演示，不是验证假设所必需。

## 场景 E：交付与验证

### E1 可用性测试

- **怎么用**：5 名用户 × 5 个任务，只观察不提示；记录任务完成率、首次点击是否正确、困惑点。
- **CrossMate**：任务“匹配后发第一条消息”——初版 3/5 找不到 AI 入口（隐藏在“…”里）→ 改成输入框左侧常驻 ✦ 按钮。

### E2 A/B 测试

- **怎么用**：先写假设与指标，再定样本与停止规则；护栏指标必看。
- **CrossMate**：E1–E5 见 `docs/04` §4。例：“匹配页加 reasons 提升 24h 首条消息率”的护栏是举报率不升。

### E3 数据驱动（事件设计）

- **怎么用**：先设计事件（用户、动作、对象、时间、属性），再谈报表。事件少而准 > 多而乱。
- **CrossMate**：26 个事件见 `docs/04` §8，每个 FR 都对应 1–2 个事件。

## 场景 F：度量与迭代

### F1 北极星 + 指标树

- **CrossMate**：WMS（周均有意义对话用户数），拆为 匹配量 × 首条消息率 × 有效对话率 × 留存。

### F2 OKR

- **怎么写**：O 是方向（可鼓舞），KR 是可量化、有基线、能影响。
- **CrossMate**：见 PRD §2.3（4 个 O，8 个 KR）。

### F3 AARRR（海盗指标）

| 阶段 | 指标 | CrossMate 手段 |
|---|---|---|
| Acquisition 获取 | 激活率 | 落地页 + 演示账号 |
| Activation 激活 | 完成资料率、首匹配率 | 资料 3 步、必填少、match_hint |
| Retention 留存 | D1/D7/D30 | 有效对话 → 积分结算 → 回访 |
| Revenue 收入 | 兑换率（当前）/ 付费率（v0.3） | 装饰兑换；**不做曝光付费** |
| Referral 推荐 | 邀请数 | MVP 不做（避免刷量） |

### F4 漏斗分析

- **怎么用**：先看**绝对量**判断是否有量，再看**转化率**找瓶颈；不要只看百分比（小样本的 100% 没意义）。
- **CrossMate**：曝光→喜欢→匹配→首条→对话→通话，见 `docs/04` §3。

### F5 留存 & 同期群

- **怎么用**：按注册周分 cohort，对比不同版本/不同行为组的曲线；回答“哪类用户活下来了、因为他们做了什么”。
- **CrossMate**：首周有过有效互动的用户 D30 留存显著更高 → 资源从“多刷卡片”转向“让匹配聊起来”。

### F6 转化率 & ROI

- **转化率**：永远同时写分子分母口径。
- **ROI**：（增量收益 − 成本）/ 成本；AI 成本按生成次数 × 平均 token 估算。CrossMate 先算“每次有效对话的 AI 成本”，再决定配额。

### F7 PDCA

- **怎么用**：Plan（假设+指标）→ Do（上线）→ Check（数据）→ Act（扩大/回滚/再假设）。
- **CrossMate 例**：AI 配额 10 次/日 → 采纳率 18% → 下调到 6 次/日并提升提示质量 → 采纳率 26%（假设数据）。

### F8 复盘

- **结构**：目标 vs 结果 → 做对了什么 → 做错了什么 → 意外发现 → 下一步。
- **原则**：复盘对事不对人；写“如果重来会怎么做”，不要写成工作总结。

## 附：两个岗位的追问对照

| 岗位 JD 关键词 | 面试可能怎么问 | 用 CrossMate 怎么答 |
|---|---|---|
| 匹配算法 | “你们的匹配怎么做的？” | 5 个特征 + 权重（合计 1.0）+ 风险扣分 + 新鲜度抖动；解释为什么敏感属性、积分、停留时长都不进公式 |
| RTC 接通率 | “接通率怎么定义？” | 双方 media_ready 才算接通（`connected_at`），否则虚高；用 `provider_event_id` 去重 |
| 男女比例平衡 | “女性用户少了怎么办？” | 不在排序里用性别；用供需指标（女性收到喜欢的质量、首日举报率）管理；用地域/语言冷启动与新人保护 |
| 付费转化漏斗 | “怎么提升付费？” | 先做非现金兑换验证意愿，再谈订阅；明确不做曝光付费 |
| 礼物系统 | “为什么不做现金礼物？” | 合规与“积分不影响推荐”自洽；非现金装饰兑换 |
| DAU/付费率/ARPU/留存/ROI | “你负责哪个指标？” | 北极星 WMS + 指标树 + 每个 KR 的埋点 |
| 本地化 | “印尼和巴西有什么不同？” | 印尼：夜间活跃、文字+语音房；巴西：语音优先；日本：礼貌语风格（`style=polite`） |
| 数据驱动 | “你怎么验证一个想法？” | 假设→事件→实验→护栏→PDCA，举例 E1/E2 |
